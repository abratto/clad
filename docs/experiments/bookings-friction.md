# Friction log — Bookings experiment (orchestrator mode)

> **Disposition.** This report is historical. It was produced on a throwaway
> `apps/bookings` clone (Java 21 + Micronaut + Postgres, package `com.bookings`)
> built on CLAD 0.29.2. The app and its feature tree are not in this repository;
> the app-specific commands below describe the tree at the time of the run. The
> platform fixes that came out of it are in **v0.30.0** (see `CHANGELOG.md`), each
> with a regression test in `quality-gate/tests/`.

Live record captured while building a small 3-UC room-booking app with CLAD
0.29.2, one sub-agent per stage, the orchestrator acting as human gate
reviewer. Status: **open** / **fixed-here** / **stale-in-old-log** / **new**.

## Summary (read this first)

36 findings across a 3-UC build + 2 iterative changes. The ones that were true
blockers or **silent false-greens** were ported as **v0.30.0** (marked
`fixed-ported`); the rest are documented for a future release.

**Ported in 0.30.0 (blockers / silent false-greens):** #5 (`Map<K,V>` state
dropped), #7 (corpus `.keys()`), #12 (`generate_syncs` emits `status`), #15
(no-op stage skips a pending gate), #17 (Rmap unquoted defaults), #18 (app-wide
Rmap drift used feature scope), #23 (citation apostrophe), #24 (companion-lag
deadlock at 04b), #25 (iterative readiness deadlock), #30 (`chain_outcomes`
latent no-op).

**Systemic / methodology (documented, need a design change not a patch):**
#16, #29 (companion lag before 04b/04a), #26/#34 (iterative change spanning a
gate needs mid-flow re-approval), #22 (new outcome on a reused concept reopens
01a), #10 (body field named `outcome` collides with the `Web.respond` token),
#19 (Postgres proof outside `test.command`).

**Fixed after the initial release:** #31 (R22 current-source wall for a
flow-owning feature) — **0.31.0** adds `./clad promote-concepts --maintenance`
plus the `Dependent re-entry` link, so an additive shared-concept change is
published by the maintenance route without relaxing R22. #32 (canonical change
ripples into frozen proposals) — **0.32.0** makes additivity compare a
re-entering feature to its own prior committed proposal, not the moving
canonical.

**Environment / test-isolation:** #27 (`test_iterative_change_coupling` fails
whenever any `_changes/` record is active — baseline unreproducible mid-change),
#21 (Postgres tests share a container; truncate in setup), #33 (stale receipt
presents a PASS for unfinished work), #20 (`--json` needs `--force`).

Historical note: two rows were renumbered `14b`/`15b` where the log double-counted
a number during the run.
