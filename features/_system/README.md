# `features/_system/` — system scope (Stage 00 + concept vocabulary)

This folder is the canonical home for **Stage 00 (Actor / Goal)** when
it is run at **system scope** — that is, for a fresh project brief that
has not yet been decomposed into individual UC folders.

It is also the canonical home for the **concept vocabulary**: the
system-scope concept corpus, its generated catalog, and the app-level
concept dependence graph. Concepts are shared, system-level assets that
use cases *compose* — they are not re-derived per UC.

## Why this folder exists

Stage 00 produces `actors.md` and `goals.md`. For a real system with
more than one goal, those artefacts describe the *whole system*, not a
single feature. Creating a `features/UC-XX-<slug>/` folder before
Stage 00 is complete is structurally wrong: the UC folders are created
**after** the goal list is confirmed, one folder per in-scope goal.

`_system/` gives Stage 00 a home that is clearly outside any UC scope.

## What lives here

```
features/_system/
├── README.md                    ← this file
├── concepts/                    ← canonical concept corpus (one file per concept)
│   └── <Name>.concept.md        ← full anatomy; provenance via `introduced-by`
├── concepts-catalog.md          ← GENERATED index (do not hand-edit)
├── concept-dependence.md        ← reviewed app-level extrinsic dependence graph
└── stages/
    └── 00_actor-goal/
        ├── CONTEXT.md           ← Stage 00 contract (system scope)
        └── output/
            ├── actors.md        ← written after human approval
            └── goals.md         ← written after human approval
```

The corpus is seeded from the worked example's concepts (`UC-00-login`,
provenance "introduced by UC-00-login"). Proposed concepts are promoted
into it only on gate approval, via `./clad promote-concepts` — never by
hand. `concepts-catalog.md` is regenerated by
`quality-gate/generate_concepts_catalog.py`; edit the corpus, not the index.

## Relationship to UC folders

Once `actors.md` and `goals.md` are approved:

1. Read every in-scope goal in `goals.md`.
2. Create one `features/UC-XX-<slug>/` folder per in-scope goal by
   copying `templates/feature-skeleton/`.
3. Run Stage 01 inside each new UC folder, carrying `actors.md` and
   `goals.md` forward as inputs.

## What does NOT live here

Every **per-use-case** artefact from Stage 01 onwards lives inside a
per-UC folder. This folder holds system-scope artefacts only: Stage 00
output, and the concept vocabulary (`concepts/`, `concepts-catalog.md`,
`concept-dependence.md`). In particular it does **not** hold per-UC
syncs, data models, SPECs, or implementation.
